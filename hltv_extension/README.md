# CS2 Pro Predictor (HLTV) — фаза 2

Панель на странице матча HLTV: протокол вето, винрейты обеих команд по каждой
карте пула и Δ между ними, **прогноз модели на будущий матч** и **пересчёт
вероятности по ходу живой серии**. Расширение не делает никаких запросов к HLTV
и ничего никуда не отправляет: `content.js` читает готовый DOM, а модель и
снимок рейтингов лежат внутри пакета.

## Установка

1. `chrome://extensions` → режим разработчика включён.
2. «Загрузить распакованное расширение» → папка `hltv_extension`.
3. Открыть любой матч: `https://www.hltv.org/matches/<id>/…`.

## Откуда модель

Не букмекерские коэффициенты и не чужой парсер — своя выборка и своё обучение:

- **Данные:** `data/hltv_results.tsv`, 35 204 строки архива `/results`
  (2023-05-18 … 2026-11-08), собраны коллектором через управляемый браузер.
- **Чистка:** убираются технические `def`, ничьи и несогласованные счета;
  остаётся 28 415 матчей (BO1/BO3/BO5).
- **Обучение:** `src/hltv_train.py` → CatBoost (depth 5, lr 0.05, l2 5,
  early stopping по июню, 52 дерева). Разрез по времени: train < 2026-06-01,
  val 06–07, test ≥ 2026-08-01 (3 274 матча, которых модель не видела).
- **Качество на test:** точных исходов **64.8%**, AUC **0.696**, Brier 0.219.
  Чистый Эло-бейслайн — 64.4% / 0.690, «всегда первая команда» — 55.7%.
  Калибровка по децилям лежит на диагонали (P=0.72 → факт 0.73).
- **Признаки (8):** `elo_diff`, `form5_diff`, `form10_diff`, `rest_diff`,
  `n30_diff`, `log_n_diff`, `is_bo1`, `is_bo5`. Все считаются хронологически
  (только матчи ДО текущего) и воспроизводятся в расширении офлайн.
  Важность: ΔElo 65.9%, опыт 22.0%, отдых 4.8%, остальное < 3%.
- **Экспорт:** `hltv_extension/model_hltv.json` (52 дерева, тот же json-формат
  CatBoost, что читает FACEIT-расширение) и `team_ratings.json` — снимок
  рейтингов 2 099 команд на `as_of` + `meta` с метриками. Сверка json против
  `models/catboost_hltv.cbm` на 500 случайных векторах: расхождение 0.0.

## Что панель считает честно

- **Вероятность всегда подписана**: чья именно и на что (вся серия / текущая
  карта), плюс обе стороны, чтобы число нельзя было прочитать задом наперёд.
- **Сыгранный матч — прогноза нет.** Если матч закончился или его дата раньше
  снимка рейтингов, панель прямо пишет, что результат уже внутри снимка и число
  было бы подгонкой задним числом.
- **Нет команды в снимке** (новый или переименованный состав) — прогноза нет,
  причина называется по имени команды.
- **Тонкий рейтинг:** меньше 20 матчей у одной из сторон — отдельное
  предупреждение.
- **Винрейты и выборка** берутся из инфобокса HLTV, окно — последние ~3 месяца.
  HLTV считает винрейт только по составу, отыгравшему вместе минимум 3 матча
  (`minLineupMatch=3`); у нового ростера панель пишет «нет игр», а не ноль.
- **Пороги статистики:** `< 5` сыгранных карт — карта не участвует в вердикте;
  `< 10` — вердикт помечается как слабый сигнал; `|Δ| < 8 п.п.` — шум.

## Live-пересчёт

Предматчевая вероятность серии разворачивается в вероятность одной карты
(бином «first to ⌈bo/2⌉», обращение бисекцией), дальше:

- **карта:** динамика MR12 — до 13 раундов, при 12:12 овертайм-блоки по 6
  раундов с победой на 4 и повтором при 3:3 (ценность ничейного блока находится
  как неподвижная точка);
- **серия:** дерево до нужного числа карт, где текущая карта считается по её
  счёту, а оставшиеся — по предматчевой вероятности карты.

Счёт берётся из скорботады HLTV: `.ctScore`/`.tScore` — это **стороны**, а не
команды, поэтому команда на CT определяется по `thead.ctTeamHeaderBg` и уже
потом сопоставляется с командами матча. Обновление — раз в 5 секунд, пока матч
живой.

Ограничение сознательное: поправки на сторону CT/T нет (в архиве `/results`
нет пораундовой статистики), поэтому точность live-числа — на уровне карты, а
не отдельного раунда. Это написано и в самой панели.

## Известные границы

- На BO1-страницах HLTV не печатает блок статистики карт — остаются вето и
  прогноз модели.
- Симуляция вето — прогноз HLTV, а не факт: её проценты подписаны как симуляция.
- Снимок рейтингов статичен: он обновляется только пересборкой
  (`python src/hltv_train.py` после дозагрузки архива).
- Прогноз — оценка вероятности, не гарантия и не совет ставить.

## Проверка без браузера

```
python tools/harness/hltv_stand.py <фрагменты.json> <имя>   # стенд из фрагментов DOM
python tools/harness/hltv_stand.py --from-stand <стенд.html> # пересобрать на свежем content.js
python tools/harness/hltv_stand.py --fetch <фрагменты.json> <имя>  # стенд ветки chrome.runtime+fetch
python tools/harness/hltv_stand.py --dp                      # стенд проверок live-динамики
python tools/harness/hltv_run.py                             # прогон всех стендов, ждём «ПРОБЛЕМ: 0»
python tools/harness/frag_server.py                          # приём фрагментов из браузера (:8766)
```

Стенды (10 штук, прогон 08.11 — «ПРОБЛЕМ: 0»): `live-og-9ine` (живая серия 1:1,
третья карта 6:8), `fetch-live-og-9ine` (те же фрагменты, но бандл грузится
через заглушку `chrome.runtime.getURL` + `fetch` — числа панели обязаны
совпасть с `live-og-9ine`), `upcoming-baks-leo` и `upcoming-balkan-exence`
(матч ещё не начался; во втором команды нет в снимке), `finished-navi-betboom`
(сыгранный матч — прогноз обязан не показаться), четыре `match-*` из фазы 1 и
`dp-unit` (44 проверки динамики: бином против дерева, границы 13:11 / 18:16 /
16:18, симметрия и монотонность счёта).

Фрагменты DOM снимаются с живой страницы (браузер гидратирует HLTV своим JS,
поэтому сохранённый HTML как стенд не годится) и лежат в
`tools/harness/hltv/fragments/`, собранные стенды — в `tools/harness/hltv/`.
Стенды не имеют `chrome.runtime`, поэтому бандл модели подкладывается в страницу
объектом `window.__hltvProBundle` — тем же, который в расширении собирается из
`model_hltv.json` и `team_ratings.json`.

Не связано с HLTV.org.
